## Technical Overview

- **FastAPI** for the web framework
- **Uvicorn** as the ASGI server
- **httpx** for async HTTP requests
- **poetry** for package management
- **Render.com** for hosting (_I'm a huge fan already but more on that in a sec_)
- **Tomorrow.io** and **Google Maps Weather API** as my data sources (_Yup, just these 2 for now..._)

Just send a GET request with the town name, and you'll get back a JSON with all the weather metrics you need to decide if you should proceed or bail on your friends.

## API & Security Design

- **X-API-KEY Authentication**: Only requests with the right header get through.
- **IP Filtering**: Only allowlisted IPs can access the endpoint.
- **Rate Limiting**: No spamming allowed. You get 10 requests a minute, and that's generous.
- **Clean Logging**: No sensitive info in the logs, just enough to know what's going on.

The last 3 listed are set up in the middleware.

The IP filtering will only allow Cloudflare IPs to come through - much like the reverse proxy pattern that I did with `sh-vegapunk/lilith` telegram bot.
Except that this time, I do intend for my cloudflare worker to also handle the responses - so it's not acting purely as a reverse proxy anymore. I'm not sure what the correct technical term here is - please let me know if you do.

## Final Thoughts

FastAPI’s documentation was genuinely a pleasure to read. The explanations were clear and the examples were easy to follow - wasn't especially hard to follow since it was all pythonic.
Deploying the app on Render was just as straightforward — similar to Vercel/Cloudflare, you simply connect your GitHub repo, and it automatically deploys from the `main`.
That said, being on the free tier means the service auto-scales down to zero when idle, so the first API call after 15 minutes takes a bit longer to respond. Still, I’m not complaining — it’s still a great deal considering that they don’t even ask for my credit card details.
