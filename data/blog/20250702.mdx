## **Introduction & Motivation**

I finally got to building my first personal portfolio website with `Next.js` hosted on `Cloudflare Pages`.

Settled on this framework because Edwin endorsed it, and it was modern, flexible, and came with plenty of documentation and support resources out there.

Also went with `Cloudflare Pages` because it was really straightforward to set up - _just push to `main`, preview environment available, no need to input credit card details, integration with KV in case I need it in future..._

## **Technical Challenges**

- **CSS & Styling**: I thought that Tailwind would save me from CSS hell, and while it mostly did, it still wasn't a very smooth-sailing experience when the SVGs struck. Figuring out how to calculate offsets and how much to scale were very foreign concepts to me, and it really was a struggle.

- **Understanding the hooks**: As the project progresses, understanding how hooks work - especially in the context of client-side navigation, state persistence and conditional rendering was tough. While attempts at understanding each hook proved to be straightforward, the actual use came with many nuances that weren't immediately obvious.
  I initially misunderstood how often hooks are re-invoked during re-renders, which led to incorrect assumptions about variable scoping. I also faced slight difficulties in something as simple as routing logic where I had to consider edge cases such as direct accesses to my blogpost.

## **What I Learned**

- **Modern frameworks are powerful, but documentation is still king.** Understanding the basics (routing, data fetching, static vs. dynamic) is key, and _good old junior dev (AI)_ really helped me structure the unknowns and provided me with concise and easily understandable explanations.
- **CSS is still the final boss.** Tailwind helps, but I still find it a struggle to make it work on my first few tries. I guess this is something that comes with more practice.
- **Launching this website comes with several layers of pressure**. Now that my site is live and publicly accessible, there's an added pressure to anticipate and handle every possible edge case so users won't break the experience. This includes ensuring robust client-side logic, protecting all API endpoints, securely injecting secret tokens only where appropriate, and carefully limiting sensitive data exposure so frontend components can't access them.

## **Final Thoughts**

Building this site was equal parts fun, frustrating, and rewarding. I learned a lot, shipped something I’m happy with, and now have a one-stop shop for all my projects and writing.
